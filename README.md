# Детекция ботов-парсеров — описание решения

**Итог:** CatBoost на 74 признаках. Precision при Recall ≥ 0.7 на временной валидации:

- **0.913** на однодневных фолдах;
- **0.892 / 0.894** на недельных блоках, устроенных как тест.

Ожидаемый результат на тесте — около 0.87–0.91.

- `solution.ipynb` — полное решение: очистка → признаки → модель → валидация → `submission.csv`.
- `experiments.ipynb` — исследования, на которых основаны выводы ниже; запускает `solution.ipynb` и добавляет эксперименты.

## Обработка данных

- Выброшены события после конца окна (12.4%): признаки должны быть доступны на момент конца окна.
- `platform` записан 11 способами, регистр меняется даже внутри одной куки. Приведён к `web` / `android` / `ios`.
- Дубликаты (~4.9 тыс.) удаляются после нормализации `platform`; события стабильно сортируются по времени.
- Пропуски структурные: курсор есть только на web, глубина выдачи — только у поиска. Они остаются `NaN`, модель обрабатывает их нативно.
- Категориальные признаки — платформа, тип клиента и семейство браузера из разобранного User-Agent.
- `cookie_id`, сырой UA и даты окна в признаки не входят.

## Признаки (74)

| группа | что описывает |
| --- | --- |
| timing (21) | интервалы между событиями, скорость, сессии, суточный ритм |
| content (28) | типы событий, глубина листания выдачи, разнообразие объявлений, категорий, городов |
| pointer (9) | есть ли курсор на web, его разброс, клики точно по краю экрана |
| client (5), cookie (2) | тип клиента и браузер из User-Agent, возраст куки |
| history (4) | популярность объявлений куки у других кук за прошлые 7 дней, без меток |
| reputation (5) | доля ботов среди кук, смотревших те же объявления в прошлые дни, по меткам |

**Главная находка:** разные куки-боты смотрят **одни и те же объявления**. Пар «бот–бот» с общим объявлением примерно в 15 раз больше, чем при случайных интересах. Отсюда группы history и reputation. Обе используют только прошлые дни, для test — только метки train. Проверено тестом: если удалить все данные после даты D, признаки для дней ≤ D не меняются.

## Валидация

Только временная: тест — неделя сразу после трейна.

1. **8 однодневных фолдов** (12–19 апреля). Модель учится на всех днях до фолда; метрика — официальный `metric.py` на объединённых out-of-fold предсказаниях.
2. **2 недельных блока, повторяющих тест.** Одна модель предсказывает неделю вперёд; признаки на метках считаются только по меткам до начала недели.

Изменение принималось, только если метрики росли в обеих схемах. Ключевые шаги проверены парным бутстрапом.

## Модель

CatBoost: 1500 итераций, темп 0.03, остальное по умолчанию, усреднение по трём seed.

- Лучший на однодневных фолдах; на неделях — на уровне ансамбля из четырёх моделей, но проще.
- С параметрами по умолчанию почти так же хорош (0.910), так что результат не держится на подборе параметров.

## Что пробовал и отклонил

- Подбор гиперпараметров на 3 фолдах по 3 дня дал +0.06, но на однодневных фолдах прирост исчез. Это был шум разбиения, поэтому схему валидации заменили.
- Без согласованного прироста: форма интервалов внутри сессий, модель устройства, биграммы событий, «взрывность» активности, пересечения объявлений в тот же день, репутация по User-Agent, городу и запросу.
- Не лучше финальной модели: ансамбль моделей, ранжирование внутри дня.

## Ограничения

- **Мобильный браузер на android** — recall 0.32 против 0.80 на web. Курсора там нет, а основная часть ботов — сервис, который имитирует человека.
- Reputation опирается на разметку прошлого, в продакшене её нужно регулярно обновлять.
- History и reputation посчитаны по выборке кук, а не по всему трафику.

## Воспроизведение

Python 3.14.4. Данные задания — `train.csv`, `test.csv`, `events.csv.gz` — положите в папку `data/` (в репозиторий они не входят) и выполните из корня репозитория:

```bash
python3.14 -m venv .venv && .venv/bin/pip install -r requirements.txt jupyterlab
.venv/bin/python -m ipykernel install --user --name avito-bots
.venv/bin/jupyter nbconvert --to notebook --execute --inplace solution.ipynb      # ~3 минуты
.venv/bin/jupyter nbconvert --to notebook --execute --inplace experiments.ipynb   # ~10 минут, по желанию
```

- Результат детерминирован: повторный запуск, в том числе в чистом окружении из `requirements.txt`, даёт тот же `submission.csv`.
- Библиотеки: pandas, NumPy, SciPy, scikit-learn, CatBoost. Всё работает локально, без внешних API и предобученных моделей.
- Метрика — `metric.py` из задания, baseline — из `quickstart.ipynb`.
